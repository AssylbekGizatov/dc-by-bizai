# Безопасность и данные

## Сообщить о проблеме

Не создавайте публичный issue с ключом, текстом реального тикета, приватными правилами или дампом базы. Передайте минимальное описание и синтетический воспроизводимый пример владельцу репозитория по уже согласованному приватному каналу. При утечке секрета сначала отзовите/ротируйте его у провайдера; удаление из текущего файла не удаляет его из истории.

## Обязательные ограничения

- Данные Grand Mobile используются только в рамках разрешённого кейса. Не пытайтесь деанонимизировать людей.
- Нельзя публиковать выгрузки, derived subsets, индексы и embeddings, содержащие данные кейса. Приватный GitHub также не является одобренным местом хранения датасета.
- История очереди, feedback, предсказания и скриншоты UI могут содержать те же данные; храните их приватно.
- Удаление данных — в течение 14 дней после объявления победителей без отдельного соглашения.
- API игры отсутствует. Ни черновик, ни одобрение в UI не выполняют действие в игре.
- Вложения представлены количеством, а не проверенными изображениями. Утверждения игрока — заявления, не установленные факты.
- Платежи, бан-апелляции, взломы и санкции не решаются автоматически.

## Защиты и их пределы

Production блокируется без сильного API-токена и внешнего корпуса. Секрет Groq живёт только в environment сервера; его нельзя вводить в поле токена UI. Набор синтетических сценариев не является действующей политикой. Исторические admin/outcome-поля не служат входом inference.

Генерация внешней LLM выключена по умолчанию. Ограничение ID цитат, проверка схемы, redaction, timeout и безопасный fallback не делают произвольную генерацию безошибочной. Человеческая проверка обязательна. Нельзя считать эвристическую confidence вероятностью правильного решения.

Один общий bearer token, SQLite и внутрипроцессный rate limiting — ограничения MVP. Для реальной команды нужны SSO/RBAC, независимые identity в аудите, управление секретами, централизованные rate limits, проверенные резервные копии, retention и внешний security review.

## Перед каждым push

```bash
make check-release
git diff --check
git status --short
git diff --cached --stat
```

Вручную просмотрите staged diff. Не используйте `git add -f` для выгрузок. Автоматический guard ловит распространённые форматы данных и ключей, но не доказывает отсутствие приватной информации в произвольном файле. Не прикладывайте реальные validation predictions к Actions artifacts.
