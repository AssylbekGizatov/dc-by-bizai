# Support Copilot: анализ обращений и очередь админа

Одна страница с двумя разделами, без входа и регистрации:

- **Анализ:** вставить обращение игрока и увидеть, как сервис его разобрал.
- **Очередь админа** (`#queue`): список обращений, черновик и кнопки «Отправить», «Править», «Эскалировать». Каждая правка и решение сохраняются в сервисе как обучающий сигнал.

Обычный HTML, CSS и JavaScript без фреймворка. Vite нужен только для dev-сервера с прокси и для сборки в `dist/`.

## Запуск

Node >= 22.12. Из этой папки:

```sh
npm ci
npm run dev       # http://127.0.0.1:5173, /api и /triage проксируются на 127.0.0.1:8000
npm test          # тесты логики страницы (vitest)
npm run build     # typecheck + сборка в dist/
```

Вместе с API: `make dev` из корня репозитория. В продакшене FastAPI отдаёт `dist/` с того же адреса (`make build && make serve`, Docker).

## Режимы

- **С API.** Если `GET /api/health` отвечает, страница отправляет обращение в `POST /api/tickets`: это тот же конвейер, что `POST /triage`, но обращение ещё и попадает в очередь. В `result` ответа лежит ровно ответ `/triage`. Тексты правил берутся из `GET /api/rules`. Вход не нужен, поэтому для демо сервис запускается без `API_TOKEN`. Если токен задан, страница покажет ошибку 401.
- **Демо.** Если API не запущен или открыт адрес с `?demo=1`, анализ идёт в браузере по ключевым словам и демо-формулировкам правил, а очередь состоит из синтетических обращений и живёт только в этой вкладке.

## Что показывает

- **Сводка:** язык, категория, приоритет, спам или повтор, нужен ли человек и почему, уверенность.
- **Текст игрока:** казахские замены cp1251 (ќ → қ и т. п.) по умолчанию исправлены, исходный вариант доступен по ссылке.
- **Что извлечено:** ник, пункт правил, доказательства, сервер, и откуда взято каждое значение.
- **Найденные правила (RAG):** какие пункты нашлись и их текст. Если игрок указал несуществующий пункт, страница об этом скажет.
- **Черновик ответа** с проверкой: пункты существуют, нет обещаний разбана, возврата или наказания, нет выводов по скриншотам, язык совпадает с языком игрока.
- **JSON:** ответ API как есть.

## Очередь админа

| Кнопка | Что делает | Запрос |
|---|---|---|
| Отправить | Помечает ответ отправленным. Отправка имитируется: интеграции с игрой нет | `PATCH /api/tickets/{id}/review` со `status: simulated_sent` и текстом черновика |
| Править | Открывает черновик для правки, «Сохранить правку» сохраняет текст | то же, `status: reviewed` |
| Эскалировать | Передаёт старшему администратору, причина обязательна | то же, `status: escalated` и `reviewer_note` |

Сервис записывает каждое изменение в историю: прежний и новый черновик, статус, заметку (`GET /api/tickets/{id}/feedback`). Это и есть обучающий сигнал. Если обращение уже изменили в другой вкладке, сервис вернёт 409, и страница загрузит свежую версию.

Разделы: Новые, Проверенные, Эскалация, Отправленные, Все. Фильтры «Нужен человек» и «Срочные P0–P1». Если очередь пуста, можно добавить синтетические примеры одной кнопкой.

## Повторы и флуд: 1 игрок, 1 проблема, 5 обращений за час

Если указать ID игрока, страница передаёт его в сервис (`player_id`, для `/triage` это `reporter_hash`). Дальше решает сервис (`backend/app/storage.py`, `check_repeat`):

- **Повтор:** та же проблема от того же игрока в пределах часа.
- **Флуд:** шестое и следующие обращения игрока за час. Лимит задаётся `FLOOD_LIMIT_PER_HOUR`, по умолчанию 5.

Обращения не отклоняются, только помечаются (`is_spam_or_duplicate`, причина в `reasons`) и уходят человеку. В демо-режиме то же самое считает страница по истории вкладки.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка страницы |
| `public/analyzer.css` | Стили |
| `public/js/analyzer.js` | Раздел «Анализ»: отправка обращения, вывод результата, повторы и флуд в демо |
| `public/js/queue.js` | Раздел «Очередь админа»: список, черновик, отправка, правка, эскалация, история правок |
| `public/js/logic.js` | Исправление cp1251, язык, источники фактов, проверка черновика, демо-анализ |
| `public/js/demo-data.js` | Демо-формулировки правил и примеры (выдуманные, не из датасета) |
| `public/assets/logo.svg` | Значок страницы |
| `src/logic.test.ts` | Тесты логики |

Скрипты в `public/` подключаются как обычные `<script>` и попадают в `dist/` без изменений. Внешних шрифтов и скриптов нет: CSP сервиса разрешает только свой адрес.

Данных хакатона в папке нет: по условиям кейса их нельзя публиковать.
