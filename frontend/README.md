# Grand Mobile — рабочее место поддержки

Vanilla HTML/CSS/JavaScript + Vite. Два связанных сценария: анализ обращения и очередь администратора. React не используется. Шрифт IBM Plex Sans размещается локально; его OFL-лицензия включена в `public/licenses/` и сборку.

```bash
npm ci
npm run dev      # http://127.0.0.1:5173; API должен работать на :8000
npm test
npm run build
```

Из корня проекта `npm run dev` запускает API и Vite вместе. Dev-прокси `/api` и `/triage` обращается к `127.0.0.1:8000`. Публикация статической сборки без API не создаёт серверную очередь.

## Данные и безопасность

- При подключённом API анализ вызывает `POST /api/tickets`; обращение сохраняется в очереди. Правки отправляются через `PATCH /api/tickets/{id}/review` с `expected_revision`.
- При конфликте 409 загружается свежая версия. Несохранённый вариант остаётся доступен для сравнения. Поздняя загрузка истории не заменяет редактор.
- Для защищённого API токен вводится через кнопку подключения. Он существует только в памяти вкладки, не записывается в Storage, URL, файлы или логи и передаётся только в заголовке same-origin API-запроса.
- Браузерная демонстрация включается только явно через `?demo=1`: анализ по ключевым словам и синтетические правила, очередь только в памяти вкладки. Недоступность API, 401 и другие ошибки никогда не переключают режим. Демо не заменяет серверную NLP/RAG-логику.
- Поиск, статус, «Нужен человек» и «Срочные P0–P1» применяются на сервере ко всей очереди. Страницы содержат до 50 обращений.
- Заметка редактируется вместе с черновиком. Причина эскалации добавляется к заметке; отмена не стирает прежние правки. После 409 можно вернуть оба поля в редактор поверх свежей версии.
- Исходный и нормализованный текст берутся из одного сохранённого обращения. Источник черновика (локальный шаблон, fallback или Groq) подписан отдельно.
- Примеры вымышлены. Текст вложений недоступен: передаётся только их количество. Оценка алгоритма не является измеренной точностью.
- «Симулировать отправку» требует явного подтверждения и лишь сохраняет статус. Ничего не отправляется в игру; санкции, возвраты и разблокировка не выполняются.
- IDs источников сохраняются вместе с разделом; совместимость с `points[].ref` в ответах текущего backend не потеряна.

## Проверки

`src/logic.test.ts` проверяет исходную логику. `src/workbench.test.ts` запускает настоящий HTML и vanilla-скрипты с синтетическим mocked API: intake, revision/conflict/recovery, late feedback, повторные клики, подтверждение симуляции, сохранение заметок и токен только в памяти. Браузерная проверка проводится отдельно на реальном локальном API.

Визуальная система: `../DESIGN.md`; контекст продукта: `../PRODUCT.md`; сравнение направлений и применённые этапы Impeccable: `../docs/design-directions.md`. Официальный Impeccable 4.8.0 устанавливается проектно командой `npx impeccable@4.8.0 install --providers=codex --scope=project` и вызывается в Codex как `$impeccable`. Установленные бинарники/навыки остаются локальными и исключены из Git/Docker.
