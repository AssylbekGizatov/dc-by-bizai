# Рабочий экран: направления и решение

Режим Impeccable: **Operate**. Инструмент поддержки, а не презентация продукта. Пользователь явно поручил команде самостоятельно сравнить варианты и выбрать сильнейший, поэтому дополнительный раунд согласования не нужен. Данные ниже синтетические. Установлен официальный Impeccable 4.8.0 (Apache-2.0), engine 0.1.18. Источники: https://impeccable.style/docs/ и https://github.com/pbakaus/impeccable. В Codex вход — `$impeccable`.

## Рассмотренные структуры

| Направление | Первый экран | Сильная сторона | Ограничение |
|---|---|---|---|
| A. Последовательная проверка | Узкая навигация слева. Обращение, сведения, правила и ответ идут вертикально. Сохранение внизу. | Удобная линейная работа на телефоне; минимум одновременно видимой информации. | На компьютере приходится прокручивать между источником и ответом; долгое сравнение. |
| B. Сравнительное рабочее место — выбрано | Тёмная верхняя навигация. Слева компактный ввод или очередь. Внутри открытого обращения — исходный текст, сведения и правила слева, редактор ответа справа. Решение и причины над рабочими областями. | Источник и формулировка видимы вместе; изменения интерфейса действительно отражают работу администратора. | Потребуется переход к одной колонке на планшете; длинные правила увеличивают высоту документа. |
| C. Трёхколоночное досье | Очередь 240 px, обращение 420 px, редактор справа; правила в выдвижной области. | Самая быстрая обработка очереди на широком экране. | Не подходит анализатору без очереди; правила скрываются во время редактирования; при 1280 px слишком узко. |

Выбран B: на широком экране он уменьшает переключение контекста; на телефоне сохраняет естественный порядок «обращение → сведения → правила → ответ». Не добавляем декоративные KPI, карточки или графики. Отличительный приём — контрастная полоса решения над двухчастным рабочим документом и видимая граница между исходными данными и ответом.

Все три направления отрендерены браузером на одном синтетическом примере. Временные HTML и PNG лежат за пределами репозитория (`work/qa/direction-a-sequential`, `direction-b-comparison`, `direction-c-three-pane`). После просмотра выбранного направления правила перемещены под источник: ответ начинается на одной высоте с исходным текстом, а не после длинных цитат. Форму можно явно свернуть с сохранением значений; на телефоне это происходит после успешного анализа. Кнопки разделов позволяют перейти сразу к ответу или источникам без изменения маршрута очереди.

## Визуальное обоснование

Для Impeccable seed рассмотрены семь источников дисциплины: архив обращений, справочный указатель, расписание смен, журнальная редактура, книжный каталог, музейный каталог, карта районов. Назначен шестой вариант (seed:70f91b394c891b27). Переносим только типографическую и цветовую дисциплину каталога: сильный контраст заголовка и пояснения, точный индекс документа, согласованные поля. Навигация, формы и редактор остаются стандартными интерфейсными элементами.

Каталожные challengers оценены по связи с аудиторией и ясности задачи: high-density web конкурентен по плотности, но мелкий текст и мозаика проигрывают чтению; manual-acetate конкурентен по разделению разделов, но декоративная материальность не помогает; coded record sleeve, video feed, garden map и type specimen проигрывают обе оси из-за скрытых подписей, однозадачного кадра или чрезмерного пространства. Из дисциплины альтернатив заимствуем ясность состояния и плотность, не их декоративные формы.

## Audit → critique → layout → typeset → adapt → harden → optimize → polish

- **Audit / critique (baseline):** в `detect()` недоступный API автоматически становился демо; очередь не имела поиска и пагинации; мелкие подписи 10–12 px; ответ и источники последовательно уходили ниже экрана; конфликт сохранял черновик, но терял заметку.
- **Layout:** сравнительный документ, отдельные области чтения и ответа; очередь становится компактной при открытии записи.
- **Typeset:** локальный IBM Plex Sans с кириллицей; основной текст 16 px, подписи 13–14 px, строки правил не растягиваются на всю ширину; кодовые идентификаторы не конкурируют с содержанием.
- **Adapt:** две рабочие колонки только при достаточной ширине; на телефоне обычный вертикальный документ, одна карточка обращения вместо списка рядом, все основные действия доступны.
- **Harden:** явное демо через `?demo=1`, ошибки сети/401/429 не меняют режим; защищённые черновики, свежий GET после 409, заметки в восстановлении, pending submit lock.
- **Optimize:** ограничение размера страницы очереди, серверный поиск, без новых UI runtime; CSS переписан как одна система вместо накопленных override-слоёв.
- **Polish:** единые focus/hover/disabled/loading состояния; согласованные подписи, семантический цвет и размеры нажатий; реальная проверка браузером и тестами фиксируется в отчёте проверки.

Эта таблица описывает принятую работу. Успешность браузерных/автоматических проверок должна подтверждаться итоговым отчётом, а не этим документом.
