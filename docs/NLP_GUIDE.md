# NLP-часть Support Copilot: как устроено и как с этим работать

Один документ про предобработку, извлечение, классификацию, модели, разметку и метрики.
Подробности по отдельным темам: разметка — `LABELING.md`, метрики — `METRICS.md`,
развёртывание — `DEPLOYMENT.md`, протокол качества — `ANNOTATION.md`.

---

## 1. Карта файлов

| Файл | Что делает |
|---|---|
| `backend/app/nlp.py` | Нормализация текста, язык, извлечение (ник, пункты правил, сервер, доказательства), правила категории и приоритета, сигналы ручной проверки. Точка входа — `analyze()` |
| `backend/app/trained.py` | Обучаемые модели: жалобы (`train`, метки из исходов админов) и репорты (`train_reports`, ручная разметка). Хэш-признаки + LogReg, файл `.npz` |
| `backend/app/classifier.py` | Необязательное уточнение через E5-прототипы (только если задан `LOCAL_ENCODER_PATH`) |
| `backend/app/taxonomy.py` | Проверка `taxonomy.json`; карта «пункт правил → категория» для подсказок |
| `backend/app/retrieval.py` | Поиск правил; ссылки с кодом (`GZ 1.1`) проверяются по своему документу |
| `backend/app/service.py` | Склейка: `analyze` → модели → правила → черновик → причины ручной проверки |
| `backend/app/cli.py` | `predict`, `evaluate` (в т.ч. по gold), `train`, `train-reports` |
| `scripts/labeling.py` | Выборка для разметки, конфиги Label Studio, деление между людьми, сборка gold |
| `backend/tests/test_handout_driven_nlp.py`, `test_report_model.py`, `scripts/tests/test_labeling.py` | Регрессии NLP, модели репортов, разметки (тексты синтетические) |
| `notebooks/` | Эксперименты выбора модели (Kaggle 2×T4) |

## 2. Путь одного обращения

```
TriageRequest (kind, messages, region, server_lang, rule_refs_raw, images_count, reported_nick …)
  │  сообщения админа и исходы (verdict, punishment, violation) отбрасываются — это ответы, не признаки
  ▼
normalize()        NFC, полноширинные символы, cp1251-казахский, узбекский апостроф, невидимые символы
detect_language()  буквы-маркеры + словари ru/kk/uz/en/es/pt → lang, уверенность, «смешанный»
извлечение          nickname · rule_refs · server · has_evidence
правила            категория по сигналам (сленг, апелляции, пункты правил) и приоритет
модель жалоб       (CLASSIFIER_PATH) уточняет категорию жалобы, если уверена
модель репортов    (REPORT_CLASSIFIER_PATH) уточняет help / question / complaint / off-topic
  ▼
Analysis → service.py: поиск правил, черновик, needs_human + reasons
```

Сервис работает и без моделей — тогда всё решают правила (accuracy ниже, см. §7).

## 3. Предобработка

- **NFC, а не NFKC**: NFKC превращает «№2.1» в «No2.1» и прячет номер правила. Полноширинные символы сводятся явно.
- **cp1251-казахский.** Игра на kz-серверах пишет казахские буквы похожими символами. `ќ→қ, ѕ→ң, ў→ұ, ї→ү` однозначны.
  Для `ґ, є, ј` текст кейса и реальные тикеты расходятся (кейс: ґ→ғ, є→ә, ј→ө; тикеты: кґмек → көмек, аєалар → ағалар,
  јзірлік → әзірлік). Решение — по позиции: рядом с гласной это согласная ғ, между согласными — гласная (ґ→ө, є→ә);
  `ј` — ө для известных ө-основ, иначе ә.
- **Где применять таблицу**: только на kz-сервере (`region="kz"` / `server_lang="kk"`) или, без метаданных, если есть
  буквы, встречающиеся только в подменах (`ќ ѕ ј ґ`). На cis-серверах `є ї і` — настоящие украинские буквы, на uz — `ў`.
- Узбекские `o'`, `` o` ``, `o’` сводятся к одному апострофу.

## 4. Язык

Буквы, которые есть только в одном языке игры (`ә ң ө ұ ү һ` → kk; `ў ҳ`, `oʻ gʻ` → uz), плюс словари частых слов.
Узбекский словарь латиницы собран по данным (слова uz-серверов, ≥ 8 раз реже на cis). `і` **не** признак казахского:
на cis-серверах много украинских обращений. Никнеймы и ссылки при определении языка вырезаются.
Языки ответа: `ru kk uz en es pt und`.

## 5. Извлечение

| Поле | Как |
|---|---|
| `rule_refs` | Номер + код документа в любом порядке: «2.1 ОП», «2.1оп», «1.1 гз», «ЖБ 1.1.2», «5,2 ОП», «п.2.1». Общие правила — просто `2.1`; остальные — `GZ 1.1`, `ЖБ 1.2.7`, `ПГО 6.3`, `FW 1.25`, `ОПГ 1.5`, `BW 1.13`, `ФУРА 1.20`. В `rules.json` 11 документов, каждый нумеруется с 1.1, поэтому без кода номер неоднозначен. Это **утверждение игрока**, применимость проверяет поиск правил |
| `nickname` | Поле `reported_nick`, иначе шаблон `Имя_Фамилия(цифры)` |
| `server` | Явный номер рядом со словом «сервер/server»; иначе `null` |
| `has_evidence` | Вложения есть **или заявлены** (ссылка `<url>`/http, «скрины есть», «фрапс»), с учётом отрицаний («скринов нет»). Не подтверждение нарушения |

## 6. Категория и приоритет

### Правила (`analyze`)
- Сленг: оск → insult; дм, дб, тк, ск, нрп, зз → dm; софт, багоюз → cheat; скам → scam.
- **Апелляция своего наказания → `complaint.admin`** («не согласен с наказанием», «опру», «за что бан», оправдания «я без софта»).
- Если в тексте нет сигнала, а игрок указал пункт («2.1 ОП»), категорию подсказывает `taxonomy.json` (`categories[].rules`).
- «Оплатить штраф» — игровой штраф, не платёж.

### Модели
| | Модель жалоб | Модель репортов |
|---|---|---|
| Обучение | `make train` (≈19 тыс. жалоб train) | `make train-reports` (ручная разметка, только `split=train`) |
| Метки | исход из шаблона ответа админа | разметка людьми |
| Когда меняет категорию | уверенность ≥ 0.4 (0.6 против явного сигнала, 0.7 против «invalid») | уверенность ≥ 0.3 |
| Чего не делает | — | не назначает и не снимает payment / account: это p0 и обязательная ручная проверка, решают только правила |

Обе модели: хэшированные char 2–5 + word 1–2 n-граммы, TF-IDF, логистическая регрессия.
**В файле модели только числа** — ни словаря, ни текстов, поэтому её можно передавать, но в Git она всё равно не кладётся.

### Приоритет
Тип проблемы решает: читы / скам / RMT — p1; оскорбления, DM, admin, other, жалоба через репорт, help — p2;
вопросы, оффтоп, invalid, жалоба совсем без доказательств — p3; взлом, угрозы вне игры, массовый баг, платёж — p0.
Правило «жалоба с доказательствами → p1» не используется: вложения есть у всех жалоб выгрузки, и p2 стал бы недостижим.

## 7. Метрики (кратко)

Test — 198 обращений, размеченных людьми; выбор моделей и порогов только на train/dev.

| Конфигурация | Категория, accuracy | Приоритет, macro-F1 |
|---|---|---|
| Только правила | 0.515 | 0.450 |
| + модель жалоб | 0.672 | 0.532 |
| + модель репортов | 0.687 | 0.532 |

Полная таблица, эксперименты с E5 и ограничения — `METRICS.md`.

## 8. Как всё запустить с нуля

Приватная папка (вне любого Git checkout), например:

```
/private/handout/    tickets_train.jsonl.gz  tickets_valid.jsonl  rules.json  taxonomy.json
/private/labeling/   manifest.jsonl  gold_test.jsonl  labelled.jsonl  test_tickets.jsonl  label_config_*.xml  tasks_*.json
/private/models/     complaint_model.npz  report_model.npz
```

```sh
# 1. окружение (зависимости зафиксированы под Python 3.12)
make setup-backend

# 2. модели
make train TRAIN=/private/handout/tickets_train.jsonl.gz MODEL=/private/models/complaint_model.npz EXCLUDE=/private/labeling/manifest.jsonl
make train-reports LABELLED=/private/labeling/labelled.jsonl MODEL=/private/models/report_model.npz

# 3. переменные (.env или окружение)
RULES_PATH=/private/handout/rules.json
TAXONOMY_PATH=/private/handout/taxonomy.json
CLASSIFIER_PATH=/private/models/complaint_model.npz
REPORT_CLASSIFIER_PATH=/private/models/report_model.npz

# 4. предсказания и оценка
make predict IN=/private/handout/tickets_valid.jsonl OUT=/private/pred.jsonl
PYTHONPATH=backend python -m app.cli evaluate --input /private/labeling/test_tickets.jsonl --output /private/report.json \
  --gold /private/labeling/gold_test.jsonl --manifest /private/labeling/manifest.jsonl
```

`EXCLUDE=manifest.jsonl` обязателен для честной оценки: размеченные тикеты взяты из train и не должны попасть в обучение модели жалоб.

## 9. Разметка

`scripts/labeling.py`: `sample` (800 строк: test 200 / dev 100 / train 500, группы «игрок или одинаковый текст» целиком
в одной части, без игроков и текстов organizer valid) → `config` (Label Studio, отдельный проект на канал, категория +
приоритет) → `split` (поровну между людьми) → `gold` (экспорт Label Studio → проверенные строки).
Правила спорных случаев и порядок работы — `LABELING.md`.

Как добавить разметку: разметить в Label Studio → `gold` → дописать строки в `labelled.jsonl` с `split=train`
(для обучения) → `make train-reports`. **Test не дообучать и не править под модель**: иначе метрика перестаёт быть честной.

## 10. Данные: что можно и что нельзя

- В Git только код, синтетические тесты и документация. `data/`, выгрузки, `*.jsonl`, `rules.json`, `taxonomy.json`,
  модели, экспорты и конфиги Label Studio закрыты `.gitignore`. Перед коммитом: `python scripts/check_release.py`.
- Данные кейса — только для Decentrathon 6.0; удалить в течение 14 дней после объявления победителей.
- Не отправлять обращения внешним сервисам без отдельного разрешения (`ALLOW_PRIVATE_DATA_TO_GROQ=false` по умолчанию).
- В тестах и примерах — только выдуманные тексты.

## 11. Тесты и типичные проблемы

```sh
APP_MODE=test ENABLE_GROQ=false PYTHONPATH=backend python -m pytest -q backend/tests scripts/tests
```

| Проблема | Причина и решение |
|---|---|
| `pip` не ставит numpy 2.5 | нужен Python 3.12 |
| На Windows падает ~20 тестов `scripts/tests` с хэшем фикстуры | `core.autocrlf=true` переписал LF → CRLF: `git config core.autocrlf false`, перевыкачать файлы |
| `UnicodeDecodeError: cp1251` на Windows | запускать с `PYTHONUTF8=1` |
| `cli predict` отказывается работать | не задан `RULES_PATH` — без настоящих правил цитаты были бы выдуманными |
| Метрики «прыгают» после переобучения | забыли `EXCLUDE=manifest.jsonl` или в `labelled.jsonl` попали строки test |
| Категория репорта не меняется моделью | уверенность < 0.3 или правила нашли payment / account — это намеренно |
