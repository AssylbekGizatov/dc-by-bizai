# Grand Mobile Support Copilot

**BizAI · Decentrathon 6.0 · Помощь игроку, основания для администратора, контроль каждого решения.**

Grand Mobile Support Copilot превращает обращение в подготовленный материал для решения: определяет язык и срочность, извлекает сведения, находит источники и предлагает короткий ответ. Всё это доступно в рабочем месте администратора вместе с очередью, заметками и историей изменений.

Результат проекта — работающий путь от входного текста до сохранённой проверки. Решение объединяет мультиязычную обработку, локальную работу с правилами, управляемую генерацию и интерфейс ежедневной поддержки.

## Ценность для Grand Mobile

| Задача поддержки | Что даёт Copilot |
|---|---|
| Разобраться в коротком сообщении со сленгом и опечатками | Исходный текст рядом с нормализованным, факты с происхождением, язык, категория и приоритет |
| Подготовить обоснованный ответ | Источники с разделом и пунктом, черновик на языке игрока, заметные причины передачи человеку |
| Работать с потоком обращений | Поиск, фильтры, приоритеты, признаки повторов, очередь и история |
| Сохранить труд администратора | Защита повторного создания, ревизии, восстановление локальных правок после конфликта |
| Контролировать внешние зависимости | Локальный режим без API-ключа, явный fallback и учёт внешних вызовов |

Эти свойства создают основу для снижения ручной подготовки ответа. Экономия рабочего времени администратора пока не измерена в пользовательском исследовании и не выражается выдуманным процентом.

## 1. Классификация и приоритет — 25%

Локальный pipeline определяет язык, категорию, приоритет, сведения о никнейме, сервере и вложениях, а также признаки спама и повтора. Используются нормализация, эвристики и optional LogisticRegression на хэшированных символьных и словных n-граммах. Дополнительный E5 encoder сравнивает текст с прототипами; он не называется обученным классификатором.

Риск проверяется независимо от модельной категории. Платежи, апелляции и взлом не теряют обязательную передачу человеку при ошибочном уточнении класса. Неизвестное сообщение в off-topic требует уточнения; отдельный узкий список приветствий может получить фиксированный ответ. Жалобы и решения о санкциях остаются за администратором.

В подготовке моделей dev/test исключаются связанными группами по пользователю, явной группе и одинаковому тексту. Для complaint это работает по переданному списку исключённых ticket_id; полнота manifest остаётся обязанностью процедуры подготовки. Gold без текстовых признаков не используется как пустой обучающий пример.

**Подтверждение:** пакетная обработка 1000/1000 valid; регрессии [safety/cache](../backend/tests/test_context_safety.py), [binary inference](../backend/tests/test_binary_model.py), [групп](../backend/tests/test_training_groups.py). Человек требуется в 988/1000 случаев в локальной конфигурации. Это доля маршрутизации, не accuracy и не доля лишних эскалаций.

Команда ранее сообщила результаты на 198 размеченных обращениях. Они сохранены с происхождением в [METRICS.md](METRICS.md), но не перенесены на изменённые серверные модели без повторной оценки.

## 2. Качество черновиков и удобство работы — 30%

Черновик помогает продолжить диалог: подтверждает тип запроса, уточняет необходимые сведения и избегает утверждений о выполненном наказании, возврате или просмотренных изображениях. По вложениям известно количество, а слова игрока остаются заявлениями.

В интерфейсе исходное обращение, сведения, источники и ответ образуют сравнительное рабочее место. Редактор анализатора явно предназначен для копирования; сохранённые изменения выполняются в очереди. При 409 загружается свежая серверная версия, а свой текст и заметку можно восстановить. Симуляция отправки требует подтверждения и отражается в истории.

Внешняя модель имеет ограниченную роль: Groq возвращает structured plan из разрешённых фраз и цитат; приложение проверяет план и собирает текст. Тайм-аут, ошибка API или недопустимый ответ приводят к local template с диагностикой причины. Поддержаны gpt-oss-20b и gpt-oss-120b; провайдер в обоих случаях Groq.

**Подтверждение:** 34 frontend-теста, TypeScript/Vite build, backend-регрессии API и хранения. Ранее выполненные браузерные проверки сохранены в [истории верификации](VERIFICATION.md). Слепая оценка полезности и естественности черновиков специалистами поддержки пока не выполнена для финального кода.

## 3. Grounding и контроль утверждений — 20%

Источником служит настоящий приватный rules.json. Локальный индекс использует BM25 и character TF-IDF; optional мультиязычные embeddings подключаются только из локальных файлов. Повторяющиеся номера различаются внутренним ключом «раздел + пункт», а публичные цитаты сохраняют формат API. Интерфейс показывает название раздела, пункт и текст источника.

Обучающие обращения, valid и старые ответы администраторов не индексируются как готовые ответы. Ссылка игрока не является доказательством нарушения. План генерации ограничен разрешёнными ссылками: модель не может добавить произвольный источник в accepted output.

**Граница реализации:** проверка существования и однозначности источника работает, но соответствие части taxonomy-selected правил конкретной ситуации и согласование подпунктов report/complaint требуют завершения. Поисковая ветка имеет эвристические relevance gates; прямая карта категорий не обеспечивает равную проверку. Поэтому система не заявляет доказанную точность цитирования на реальных обращениях.

Историческое сравнение на 18 синтетических сценариях показало 15/15 target hit@3 и 3/3 отказа для BM25 + character TF-IDF. E5 на этом малом наборе не добавил попаданий и увеличил задержку. Это обоснование экономного режима, не оценка релевантности production-потока; детали в [VERIFICATION.md](VERIFICATION.md).

## 4. Казахский и узбекский — 15%

Обработка выполняется локально: учитываются казахские cp1251-подмены, узбекская кириллица и варианты апострофов, идентификаторы отделяются от определения языка. Никнейм латиницей внутри русского сообщения сам по себе не делает текст английским. Исходное обращение остаётся доступно для сравнения с нормализацией.

Фактические ответы через HTTP на синтетический вопрос оплаты, режим local_template:

| Язык | Черновик |
|---|---|
| ru | Приветствую! Вопрос оплаты проверит специалист. Укажите дату, сумму и способ оплаты; номер карты, пароли и коды не присылайте. |
| kk | Сәлеметсіз бе! Төлем мәселесін маман тексереді. Төлем күнін, сомасын және тәсілін көрсетіңіз; карта нөмірін, құпиясөз бен кодтарды жібермеңіз. |
| uz | Salom! To‘lov masalasini mutaxassis tekshiradi. To‘lov sanasi, summasi va usulini ko‘rsating; karta raqami, parol va kodlarni yubormang. |

Во всех трёх проверках определён соответствующий язык, категория report.payment и needs_human=true, список цитат пуст. Это узкая проверка сценариев; качество сленга, смешанных сообщений и естественности требует оценки носителями отдельно по каждому языку.

## 5. Скорость и экономичность — 10%

Основной путь работает локально на CPU без внешнего API. Модель генерации необязательна; её недоступность не останавливает подготовку безопасного шаблона. Кэш связан с полным контекстом запроса, анализом, версией правил и экземплярами загруженных моделей.

| Замер | Результат | Условия |
|---|---|---|
| Полный HTTP POST /api/tickets | 12/12 HTTP 201; p50 14,11 мс; p95 17,49 мс | N=12, concurrency=1, warm server, реальные правила, синтетические ru/kk/uz обращения, local_template |
| Пакетный predict | 1000/1000; 0 внешних вызовов | Настоящий valid; без обучения, без dense и серверных LR-артефактов |
| Внешняя стоимость текущих прогонов | $0 | Локальный режим; инфраструктура и электроэнергия не оценивались |
| Исторический live Groq smoke | 12 успешных вызовов; $0.0011322 суммарно | Два gpt-oss, синтетические данные; usage estimate, не новый замер финального кода |

Заданные ориентиры ≤5 с p95 и ≤$0.002 на обращение сопоставимы только с одинаковыми режимами и условиями. Локальная задержка не подменяет полный Groq-путь; малые smoke-наборы не доказывают production SLO.

## Инженерная целостность

Vanilla/Vite → FastAPI → локальный NLP и правила → черновик → SQLite и проверка администратором. Один сервис, понятные границы модулей и воспроизводимый запуск. Сохранены POST /triage, API очереди и JSONL predict. Авторизация, bounded input, HTTP rate limit, приватные файлы, ревизии и короткие транзакции входят в автоматические проверки.

**402 Python-теста прошли, 2 пропущены; 34 frontend-теста и build прошли.** Пропуски Windows связаны с symlink-привилегиями. Итоговый прогон не повторял Docker rebuild, полный браузерный E2E и платный Groq после командных изменений; старые результаты явно отделены.

## Данные, воспроизведение и следующий рубеж

118337 train / 1000 valid проверены в приватной рабочей области. В завершающем прогоне обучение не запускалось, valid служил только входом predict. Старые admin outcomes могли использоваться как слабые метки обучения complaint, но не как признаки inference. Данные, правила, веса, очереди и приватные отчёты не публикуются.

Следующие проверяемые рубежи — завершить проверку применимости прямых цитат, повторить оценку серверных моделей на замороженном gold, провести экспертную оценку черновиков ru/kk/uz и заново проверить полный контейнерный/браузерный путь. Персональные роли и SSO остаются за пределами текущего общего административного токена.

Сильная сторона проекта — соединение понятной помощи игроку с контролем администратора: ответ сопровождают исходные сведения, источники, причины проверки и сохранённая история решения. Именно этот полный рабочий сценарий делает Copilot полезной основой для пилота поддержки.
