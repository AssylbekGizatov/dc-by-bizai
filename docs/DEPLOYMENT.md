# Развёртывание и эксплуатация

[Проверка последнего кода](DEADLINE_VERIFICATION.md) подтверждает локальный запуск и HTTP smoke. Docker build/runtime был проверен на предыдущем этапе; повторная сборка после последних командных изменений не выполнена. Публичное размещение не выполнено и не требуется для демонстрации.

## Границы

Репозиторий содержит конфигурацию развёртывания, но не обещает существующий публичный адрес. Код игры и API отправки не предоставлены: кнопка отправки фиксирует только **симуляцию** в локальном журнале.

Локальная демонстрация запускается без ключей. Публичный demo-сервис нельзя считать защищённым только потому, что данные синтетические: незнакомый посетитель может вставить собственные персональные данные или изменить очередь. Для размещённой админки задайте `API_TOKEN` и ограничьте сетевой доступ. Production требует отдельного согласования данных, хостинга и внешних процессоров.

## Закрытый сервер с Docker

1. Проверьте `make check` и соберите `docker build -t grandmobile-copilot .`.
2. Храните одобренные правила и таксономию вне Git и build context.
3. Создайте сильный токен через менеджер секретов. Не сохраняйте его в исходниках, браузерном bundle, скриншотах, логах или shell history.
4. Создайте **локальный игнорируемый** `compose.private.yaml`:

```yaml
services:
  copilot:
    environment:
      APP_MODE: production
      API_TOKEN: ${API_TOKEN:?Set a strong admin token securely}
      RULES_PATH: /private/rules.json
      TAXONOMY_PATH: /private/taxonomy.json
      CLASSIFIER_PATH: /private/complaint_model.npz   # make train … MODEL=…; без него — только правила
      REPORT_CLASSIFIER_PATH: /private/report_model.npz   # make train-reports …; без него репорты — только правила
      ENABLE_GROQ: "false"
      ALLOW_PRIVATE_DATA_TO_GROQ: "false"
    volumes:
      - type: bind
        source: ${PRIVATE_RULES_FILE:?Set absolute rules path}
        target: /private/rules.json
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: ${PRIVATE_TAXONOMY_FILE:?Set absolute taxonomy path}
        target: /private/taxonomy.json
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: ${PRIVATE_MODEL_FILE:?Set absolute complaint model path}
        target: /private/complaint_model.npz
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: ${PRIVATE_REPORT_MODEL_FILE:?Set absolute report model path}
        target: /private/report_model.npz
        read_only: true
        bind:
          create_host_path: false
```

5. Дайте UID/GID `10001:10001` только необходимое право чтения файлов. Не делайте приватные выгрузки world-readable ради запуска.
6. Запустите `docker compose -f compose.yaml -f compose.private.yaml up --build -d`.
7. Убедитесь, что `/ready` успешен, запросы к защищённому API без токена возвращают 401, с токеном — ожидаемый результат; синтетический корпус не принимается за production-правила.
8. Оставьте port mapping на `127.0.0.1`. Внешний доступ организуйте через TLS reverse proxy с SSO/VPN или allowlist. Не расширяйте CORS до `*`.

`DATABASE_PATH` в контейнере фиксирован `/var/lib/copilot/copilot.sqlite3`; named volume хранит обращения, feedback и журнал. Резервные копии, доступ и удаление этого volume подчиняются тем же ограничениям, что и исходные данные. `docker compose down` сохраняет volume; `down --volumes` **удаляет его безвозвратно**, поэтому не используйте эту опцию без отдельного решения об удалении.

## Необязательная конфигурация Railway — без выполненного развёртывания

`railway.json` указывает корневой Dockerfile и `/ready`; контейнер слушает назначенный платформой `PORT`. Используйте корень репозитория как build context, а не `backend/` или `frontend/`. [Официальное описание развёртывания Railway](https://docs.railway.com/deployments).

Перед первой публикацией нужно подтвердить аккаунт/проект, бюджет и допустимость размещения данных в выбранном регионе. Не создавайте платные ресурсы или аккаунты автоматически из CI. Workflow этого репозитория **не деплоит** приложение и не содержит cloud/API credentials.

Для безопасной синтетической демонстрации:

- `APP_MODE=demo`, `ENABLE_GROQ=false`, `ALLOW_PRIVATE_DATA_TO_GROQ=false`;
- `API_TOKEN` в секретах платформы; не путать с `GROQ_API_KEY`;
- runtime SQLite на постоянном volume с корректными правами UID 10001, если нужна сохранность очереди;
- без приватных данных, правил и весов в образе/репозитории;
- защищённый доступ к админке.

Production дополнительно требует approved rules/taxonomy, безопасно доставленные приватным путём после разрешения владельца. Один лишь `APP_MODE=production` не обеспечивает соблюдение требований. Readiness не заменяет проверку authentication и privacy.

После запуска проверьте **терминальный `SUCCESS`**, `/ready`, авторизацию API, загрузку UI и один синтетический сценарий через полный цикл. `QUEUED`/`BUILDING` — не успешное развёртывание. Если подключения Railway нет, восстановите его; не обходите авторизацию найденными токенами или переносом секретов.

## Эксплуатационные ограничения MVP

- Один процесс API и один SQLite writer. Не добавляйте несколько реплик с независимыми базами; сначала нужен общий datastore и общий rate limiter.
- Текущий токен даёт общий доступ администратора: нет персонального RBAC/SSO, ротации сессий и независимого audit identity.
- Не публикуйте тела тикетов в access/error logs. Стандартная команда отключает Uvicorn access log; proxy logging также должно редактировать чувствительные поля.
- Внутрипроцессные ограничения/cache не являются защитой от распределённой атаки.
- Нативные носители должны проверить казахские и узбекские ответы до пилота.
- Включение внешней генерации означает отдельное решение о передаче данных и затратах. Redaction снижает риск, но не гарантирует полной анонимности.

## Откат

Сохраните SHA/образ последнего проверенного релиза. При отказе верните предыдущий образ и проверьте совместимость SQLite до подключения боевых данных. Не удаляйте volume для «исправления» ошибки. Для изменения схемы и миграций предварительно нужны согласованная резервная копия и проверка восстановления.

## Воспроизводимый локальный режим

Самый короткий запуск Windows/Linux через установленные зависимости — `npm run build && npm start` (в PowerShell команды можно выполнить по отдельности). Адрес по умолчанию 127.0.0.1:8000. Установка описана в корневом README.

Оставьте TRAIN_PATH пустым, если нужны только предсказания. Локальные LR и E5 подключаются существующими приватными путями; обучение и загрузка весов не требуются для запуска baseline. Если используете приведённый Docker override без моделей, удалите соответствующие CLASSIFIER_PATH/REPORT_CLASSIFIER_PATH и два model bind mount: остальные параметры и авторизацию сохраняйте.

Не применяйте опубликованные исторические метрики к новому образу автоматически. Перед пилотом повторите build/readiness/auth, сохранение и конфликт, браузерный цикл и замер в фактическом режиме генерации.
