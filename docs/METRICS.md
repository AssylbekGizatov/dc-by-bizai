## Как получен test

- **198 обращений, размеченных людьми** (категория и приоритет) по `docs/LABELING.md`.
  Взяты из train организаторов, не пересекаются ни с игроками, ни с текстами organizer valid.
  Состав повторяет valid организаторов (≈82% жалоб, ≈12% uz). Ответы админов разметчики не видели.
- Каждое обращение разметил **один** человек: согласие разметчиков (kappa) не измерялось.
- Модели и пороги выбирались **только** на train/dev; test считался в конце.
- 200 задач было в выборке, 2 не размечены — в метриках 198.

Команда (приватные пути, данные вне Git):

```sh
make train TRAIN=/private/tickets_train.jsonl.gz MODEL=/private/complaint_model.npz EXCLUDE=/private/manifest.jsonl
make train-reports LABELLED=/private/labelled.jsonl MODEL=/private/report_model.npz
CLASSIFIER_PATH=/private/complaint_model.npz REPORT_CLASSIFIER_PATH=/private/report_model.npz \
  PYTHONPATH=backend python -m app.cli evaluate --input /private/test_tickets.jsonl --output /private/report.json \
  --gold /private/gold_test.jsonl --manifest /private/manifest.jsonl
```

## Модели

| Модель | Данные | Метки | Признаки |
|---|---|---|---|
| Жалобы (`trained.py: train`) | ≈19 тыс. жалоб train, без 800 размеченных тикетов | исход из шаблона ответа админа (`violation`, `verdict`) | hashed char 2–5 + word 1–2 n-граммы, TF-IDF, LogReg |
| Репорты (`trained.py: train_reports`) | 192 размеченных репорта train-части выборки | ручная разметка; часть train-меток предразмечена моделью и проверена, из 192 строк 42 — синтетические примеры редких классов (payment, account), только в train | те же hashed-признаки, LogReg C=4 |

Файлы моделей содержат только числа (хэш-признаки, веса, idf) — ни словаря, ни текстов; хранятся вне Git.
Модель репортов уточняет только help / question / complaint / off-topic: платёж и аккаунт (p0, обязательная
ручная проверка) назначают и снимают лишь правила. Порог 0.3 выбран на dev (18 репортов: правила 0.611,
с моделью 0.778 accuracy).

## Эксперименты (выбор подхода, на dev)

Обучение на 568 строках train выборки, оценка на 100 строках dev, Kaggle 2×T4:

| Подход | dev accuracy | dev macro-F1 |
|---|---|---|
| char TF-IDF + LogReg | 0.69 | 0.657 |
| multilingual-E5-large (заморожен) + LogReg | 0.62 | 0.630 |
| multilingual-E5-base + LogReg | 0.66 | 0.590 |
| multilingual-E5-small + LogReg | 0.60 | 0.575 |
| дообучение E5-base | 0.58 | 0.439 |
| правила | 0.53 | 0.408 |

В этом историческом dev-эксперименте n-граммы с линейной моделью дали более высокий результат, чем замороженные и дообученные энкодеры,
поэтому в сервисе — hashed n-граммы + LogReg. Дальнейший перебор (TF-IDF × энкодеры × признаки правил,
5-fold CV) — `notebooks/gm_nlp_experiments_v2.ipynb`.

## Ограничения

- Accuracy и macro-F1 — на 198 обращениях одного разметчика; доверительные интервалы широкие (±6–7 п.п. для accuracy).
- Слабые места: казахский и узбекский (мало примеров), `complaint.invalid` / `complaint.other`, help против off-topic в репортах.
- Модель жалоб учится на исходах админов, а не на заявленной игроком проблеме: это слабая разметка.
- Confidence не откалиброван и не является вероятностью правильного ответа.
