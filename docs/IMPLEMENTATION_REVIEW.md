## Карта модулей

- Vanilla frontend: `frontend/index.html`, public CSS и JS; Vite обслуживает/собирает локальные шрифты и статические файлы. React не добавлен.
- FastAPI `main.py`: `/triage`, CRUD очереди, review/feedback, правила, health/readiness. `schemas.py` задаёт границы полей, `config.py` — конфигурацию.
- `service.py`: локальный разбор, классификация, retrieval, опциональная генерация и сохранение. `storage.py`: SQLite, история, revisions, dedup.
- `nlp.py`/`classifier.py`: эвристики и optional E5 prototypes, не обученный классификатор. `retrieval.py`: BM25/character TF-IDF и optional локальные embeddings.
- `generation.py`: проверяемая композиция локальных фраз; Groq выбирает структурированный план, не получает право выполнять действия.
- `cli.py`: очищенный от ответов администратора пакетный predict/evaluate. Данные, правила, SQLite, веса и приватные результаты находятся вне Git.

## Исходные проверки на Windows / Python 3.12 / Node 24

Frontend: 23 tests passed, build passed. Backend: 78 passed, 3 failed; ошибки касались POSIX fchmod и POSIX-only assertions приватных файлов. Scripts tests: collection failed из-за fcntl. Эти результаты сохранены отдельно до изменений. Linux baseline в этой среде не запускался.

Исходный private validation run воспроизведён; это оценка поведения без эталонных категорий/приоритетов. Метрики и данные отчёта сохраняются приватно; кодовая документация не содержит производных выборок.

Первоначальная проверка Docker была заблокирована сбоем Docker Desktop: недоступен analytics socket, Linux engine pipe не создавался. После сообщения владельца повторная CLI-проверка увидела рабочий engine. Итоговый образ собран и запущен локально; readiness, сохранение, конфликты, перезапуск и конфиденциальность проверены отдельно, см. VERIFICATION.md. Factory reset не выполнялся, существующие пользовательские контейнеры и тома не затрагивались. GitHub Actions по-прежнему завершался до получения runner; успешный hosted CI не заявляется.
