# Ручная проверка качества

Категории и приоритеты handout не размечены. `confidence` — эвристическая оценка, не accuracy и не калиброванная вероятность. Ответ администратора, исход жалобы и наказание не являются эталоном категории или безопасного черновика.

## Подготовка приватной выборки

Запустите из корня проекта с активированным Python окружением:

```sh
python scripts/audit_data.py --train /private/tickets_train.jsonl.gz --valid /private/tickets_valid.jsonl --output /private/audit.json --annotation-output /private/to-label.jsonl
```

Скрипт проверяет реальные числа строк, наличие меток и пересечения. Он берёт 120 строк только из train, исключает пользователей и нормализованные тексты из valid, сбалансированно покрывает пары языка/канала с фиксированным seed. Язык исходного набора — только подсказка для стратификации. Это не случайная репрезентативная оценка распространённости ошибок. Все метки изначально пусты. В input отсутствуют ответы администраторов, verdict, punishment, violation и итоговый статус.

## Инструкция разметчику

1. Читайте только сообщения игрока и предоставленные метаданные. Никнейм на английском не определяет язык предложения. Отметьте смешанный текст в notes и выберите основной язык; если смысла недостаточно, используйте und.
2. Выберите category из выданной taxonomy.json по каналу и смыслу. Не создавайте новые категории. В неоднозначном случае запишите альтернативу и причину, не угадывайте.
3. Выберите priority по критериям taxonomy. Оплата, потеря доступа, взлом, массовая неисправность и угрозы вне игры требуют особого внимания.
4. Отдельно заполните mandatory_human и причины: платёж, апелляция наказания, взлом/доступ, решение о наказании. Это отдельная задача от категории и общей полезности передачи человеку.
5. Сопоставьте ситуацию с полным текстом правила. Запишите внутренний UID раздела и пункта; одинаковые публичные номера в разных разделах различны. Указанный игроком номер — утверждение, требующее проверки. Если релевантного пункта нет, оставьте список пустым.
6. Для повторов учитывайте одного игрока, одну проблему и часовое окно. Общие фразы разных игроков не являются одним делом.
7. Не заполняйте факты на основе недоступных изображений: известно только количество вложений.

Два независимых разметчика оценивают каждую строку. Третий разрешает разногласия; храните annotator, adjudicator и notes приватно. Переведите status в adjudicated только после решения. Для ru/kk/uz нужны носители языка, особенно для сленга и смешанных сообщений.

## Измерения после согласования

- Категория: accuracy и confusion matrix; приоритет: macro-F1 по p0–p3. Публикуйте N, распределение классов, правила разбиения и интервалы неопределённости.
- Обязательная передача: число пропусков и recall по каждому опасному сценарию. Лишние передачи считать только относительно ручной оценки; общий needs_human rate не равен false-positive rate.
- Правила: relevance@k и корректность конкретной цитаты (раздел + пункт + соответствие смыслу); существование номера само по себе недостаточно.
- Черновики: слепая оценка 1–5 отдельно по языкам, полезность, достоверность, естественность, запрещённые обещания; не показывать оценщику режим генерации.
- Дедупликация: precision/recall пар и групп, отдельно точные и перефразированные повторы.
- Производительность: HTTP end-to-end p50/p95, ошибки, cold/warm, concurrency, режим, модель, usage и стоимость. Локальный поиск и полный Groq-путь публиковать отдельно.

Для любых моделей делите размеченный train по связанным компонентам «пользователь или одинаковый текст», фиксируйте seed и замораживайте holdout до настройки. Organizer valid и скрытый тест не индексируются как ответы и не используются для обучения. До независимых меток не заявляйте accuracy, F1 или снижение лишних эскалаций.
